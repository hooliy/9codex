# 受监督任务编排

主会话只负责理解、决策、调度、监督、验收、汇总；实现工作交给子 Agent。子 Agent 自报完成仅表示“待验收”，不表示任务完成。

## 适用边界

- 非简单、可拆分、多步骤、多模块任务默认触发。
- 简单一行改动或无法独立验收的强耦合串行任务不滥拆，由单 Agent 顺序完成。
- 仅并行文件、目录、进程、端口、账号、浏览器等资源不冲突的业务模块。

## 强制流程

### 1. 理解、确认、定义判据

先理解并向用户完整复述目标、范围、约束、产物、不做事项，等待用户确认。未确认，不下发。

下发前定义完成判据，保证可执行、可验证：

- 允许修改、必须产出的文件。
- 测试、构建、检查命令及预期结果。
- 必须核对的实际输出或行为。
- 禁止事项、资源边界。

用户判断优先纳入完成判据。模糊判断改写为可观察结果。

### 2. 按无冲突边界拆分

按业务边界拆分，保证文件与资源不冲突。每项写明目标、上下文、修改范围、完成判据、验收命令、预期输出、依赖、资源占用。无冲突任务并行；冲突或依赖任务串行。用户指定拆分时优先采用，发现冲突先修正。

### 3. 下发即公开

下发后立即在主会话展示：

```text
[任务下发]
Agent 名称：<name>
Agent ID：<id>
任务：<完整任务>
完成判据：<逐条列出>
状态：执行中
```

不得只在侧栏创建 Agent，不向用户公开任务身份和判据。

### 4. 使用准确生命周期

支持两种受监督模式：

#### A. 一次性子 Agent

`delegate_task` 或等价的一次性子 Agent：父任务必须收到完成通知；返回后自动结束、不可续聊、不可调用 `close_agent`。验收失败时携带失败证据新派修正 Agent。

#### B. `multi_agent_v1` 可续聊子 Agent

1. 用 `multi_agent_v1.spawn_agent` 创建。
2. 用 `wait_agent` 等待进度、完成通知或需关注事件。
3. 跑偏时用 `send_input` 立即纠偏。
4. 验收失败时优先用 `send_input` 交回同一 Agent 修复。
5. 验收通过后调用 `close_agent`。

工具名不同时，按两种模式的等价受监督语义判断。一次性模式必须具备下发、父任务完成通知、自动结束；可续聊模式必须具备创建、等待、继续输入、关闭。

禁止用 `create_thread`、`codex exec` 替代受监督子 Agent；缺少完整父子生命周期时不得声称受监督。

### 5. 完成通知先公开原始报告

收到完成通知后，先在主会话逐字完整转呈子 Agent 原始验收报告：

```text
[子 Agent 报告｜待验收]
Agent 名称：<name>
Agent ID：<id>
原始报告：
<原文完整转呈，不删节、不改写>
状态：待主会话验收
```

不得只做摘要；不得删掉失败、警告、遗留问题；不得在主验收前宣布完成。

### 6. 主会话亲自验收并公开证据

主会话不采信子 Agent 自报。必须亲自检查：

1. 目标文件和修改范围。
2. `diff`，确认无越界修改、冲突、遗漏。
3. 完成判据要求的测试与构建。
4. 实际输出、行为、产物。
5. 每条完成判据的通过或失败。

在主会话逐条展示命令、结果、判据与证据：

```text
[主会话验收]
命令：<原始命令>
结果：<退出码及关键原始输出>
判据：<对应完成判据>
证据：<文件、diff、测试、构建或实际输出>
结论：通过｜失败
```

子 Agent 日志只能作为线索，不能替代主会话执行。

### 7. 失败公开、纠偏、循环

验收失败时，主会话展示失败证据：命令、错误原文、文件、行号、预期、实际；同时展示发给 Agent 的纠偏内容。

```text
[验收失败｜纠偏]
Agent 名称：<name>
Agent ID：<id>
失败证据：<完整证据>
纠偏内容：<发送给 Agent 的原文>
状态：修复中
```

- `multi_agent_v1`：用 `send_input` 交回同一 Agent 修复，重新调用 `wait_agent`；收到新报告后再次完整转呈、再次验收。
- 一次性 Agent：因不可续聊，新派修正 Agent；再次完整转呈新报告、再次验收。
- 未通过继续循环，不因 Agent 自称完成退出。

### 8. 通过后关闭并公开状态

可续聊 Agent 验收通过后调用 `close_agent` 自动关闭，无需用户手动回收。

`multi_agent_v1` Agent 验收通过后调用 `close_agent`，再在主会话展示 Agent 名称、Agent ID、`close_agent` 返回结果、运行状态：

```text
[Agent 回收]
Agent 名称：<name>
Agent ID：<id>
close_agent 返回结果：<原始结果>
运行状态：closed｜关闭失败
```

准确说明：runtime 关闭不等于右侧历史卡片消失；历史卡片可能继续显示，但不代表 Agent 仍在运行。

一次性 Agent 已自动结束，不调用、也不得声称调用 `close_agent`；展示其运行状态为“自动结束”。

### 9. 停止、持久任务、硬阻断

- 普通子 Agent 随主会话停止而终止。
- 跨会话、长周期任务使用 Kanban 持久任务队列，保存任务、判据、负责人、状态、证据、失败原因、下一步。
- 外部凭据、生产授权、平台超时属于硬阻断。确认无法自主解决后报告证据并请求用户裁决；不得伪报完成。

### 10. 最终报告

全部任务逐条验收通过并完成对应生命周期后才报告完成。最终报告必须包含：全部 Agent 原始报告、主验收记录、纠偏记录、关闭状态、遗留问题。

同时列出子任务、修改文件、主会话实际运行的测试/构建/检查命令、每条完成判据的结论与证据。没有遗留问题，明确写“无”。

任一判据未通过，明确报告“未完全完成”、阻断项、失败证据、下一步，禁止输出完成结论。

## 审计边界

不得泄露隐藏推理。只展示可审计的操作、原始输出、证据、结论；不展示内部思维链。
